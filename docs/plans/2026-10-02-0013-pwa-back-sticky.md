# Installable App, Back Button, Sticky Top and Favicon Implementation Plan

> **For agentic workers:** Use executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make quickmeet installable to a home screen (a PWA), and make it usable there without browser chrome: a Back button in the lobby, History and Settings, a top bar and "New call" button that stay in view on the room list, and a real favicon.

**Tech Stack:** static HTML/CSS/JS in `resources/public/`, let-go routes (`src/quickmeet/routes.lg`), a dependency-free Node script for the icons, `lgx test` and Playwright (`lgx e2e`).

---

## Design

### Why these four things belong together

Installed to a home screen, the app opens in its own window with no address
bar and no browser Back button. On an iPhone that is also the only way to lose
Safari's bars (`docs/KNOWLEDGE.md`, "The pages"). Without browser chrome, a
person in the lobby, History or Settings has only the brand link to get back
to the room list, and on a long list the menu and "New call" scroll away. The
favicon is the same set of icon files, so it is generated by the same script.

### 1. Installable (PWA), without a service worker

- A web app manifest at `/static/manifest.webmanifest`, linked from every page:

  ```json
  {
    "name": "quickmeet",
    "short_name": "quickmeet",
    "description": "A video call between two people.",
    "id": "/",
    "start_url": "/",
    "scope": "/",
    "display": "standalone",
    "background_color": "#111312",
    "theme_color": "#111312",
    "icons": [
      { "src": "/static/icon-192.png", "sizes": "192x192", "type": "image/png", "purpose": "any" },
      { "src": "/static/icon-512.png", "sizes": "512x512", "type": "image/png", "purpose": "any" },
      { "src": "/static/icon-512.png", "sizes": "512x512", "type": "image/png", "purpose": "maskable" }
    ]
  }
  ```

  A manifest's `scope` is not limited by where the manifest file lives (that
  rule is for service workers), so `/static/...` can declare scope `/`.
- **No service worker, no offline mode, no Web Push.** Chrome (Android and
  desktop) no longer needs a service worker to offer installation, and iOS
  "Add to Home Screen" never did. A video call needs the network anyway.
  Ringing via Web Push stays where `docs/ROADMAP.md` has it ("After v1"); this
  plan delivers the "installable" half of that item only.
- iOS reads `apple-touch-icon` (a 180 px PNG) for the home-screen icon and
  honours the manifest's `display: standalone`. No `apple-mobile-web-app-*`
  meta tags.
- `theme-color`: the app pages follow the system's light or dark, so they get
  two metas with `media` (`#f4f5f2` light, `#111312` dark, the `--bg` values in
  `app.css`). `room.html` keeps its single `#111312`.
- The server change is two content types in `routes.lg`
  (`webmanifest` → `application/manifest+json`, `png` → `image/png`) plus
  `ico` for the favicon. Binary files already survive `io/slurp`
  (`docs/KNOWLEDGE.md`, "The pages").

### 2. Icons and the favicon: one script, no dependencies

`scripts/make-icons.mjs` (task `lgx icons`) writes four files into
`resources/public/`, drawn from the same two shapes as `icon.svg` (a `#111312`
square, a `#45c285` disc of radius 7/32 of the side, centred):

| File | Size | Shape | Used by |
|---|---|---|---|
| `icon-192.png` | 192 | full-bleed square | manifest |
| `icon-512.png` | 512 | full-bleed square | manifest (`any` and `maskable`) |
| `apple-touch-icon.png` | 180 | full-bleed square | iOS home screen |
| `favicon.ico` | 32 | rounded square (radius 8/32, transparent corners), as `icon.svg` | browsers' tab icon |

- Full-bleed for the app icons because Android (maskable) and iOS cut their
  own corners; the disc sits well inside the maskable safe zone (a centred
  circle of radius 40%).
- Pure Node, nothing to install: render RGBA into a buffer with 4x4
  supersampling (so the disc and the rounded corners are antialiased), encode
  PNG by hand (signature, `IHDR`, one `IDAT` from `zlib.deflateSync`, `IEND`,
  CRC-32 per chunk; Node's `zlib.crc32` exists in Node 22+, the project runs
  Node 24). `favicon.ico` is the ICO container around one 32 px PNG (6-byte
  header, one 16-byte directory entry, then the PNG bytes), which every
  current browser reads. Output must be deterministic: two runs, identical
  bytes. The generated files are committed, like the other vendored assets.
- Favicon wiring: a new route `GET /favicon.ico` (browsers ask for that path
  on their own, and Safari ignores SVG favicons) serving
  `public/favicon.ico` as `image/x-icon`; every page's head gets
  `<link rel="icon" href="/favicon.ico" sizes="32x32">` before the existing
  SVG link, so browsers that take SVG keep the sharp one.

### 3. Back button in the lobby, History and Settings

- A link at the left of the top bar, before the brand:
  `<a id="back" class="back" href="/"></a>`, filled by
  `setIcon($('back'), 'back', 'Back')` with a new chevron-left `back` icon in
  `ui.js`. Its accessible name is "Back".
- **It is a link to `/`, not `history.back()`.** A lobby opened from a shared
  link, or the first page of an installed app, has no history to go back to;
  "back" in this app always means the room list. A guest gets the signed-out
  landing page, the same place the brand link already leads.
- Room page: shown in the lobby and on the "link does not exist" state,
  hidden in a call (CSS: `.in-call .back { display: none; }`, beside the rule
  that hides the brand there). Leaving the page unloads it, which releases
  the camera.
- `settings.html` does not load `ui.js` today; it gains the script tag.
- Not on sign-in or sign-up (not asked for; they link to each other and the
  brand).
- Style: reuse the look of `button.icon` (36 px, muted, hover background) for
  `.back`, and pull it left by a few pixels (negative margin) so the chevron,
  not its padding, lines up with the page's left edge. The bar's `gap: 18px`
  between back and brand is too wide; give `.back` a negative right margin or
  equivalent so the pair reads as one group.

### 4. Sticky menu and "New call" on the room list

- The top bar becomes sticky on every app page (`body:not(.room) .bar`:
  `position: sticky; top: 0; z-index: 2; background: var(--bg)`). One rule
  for all app pages rather than a special case for the list: History can be
  long too, and the Back button should stay reachable there. The room page
  is untouched (in a call its bar is absolutely positioned over the video).
- On `index.html` the "New call" button moves into a wrapper,
  `<div class="pinned">`, inside `#signed-in`:
  `position: sticky; top: 56px` (the bar's height), `z-index: 1`,
  `background: var(--bg)`, with a little bottom padding so rows do not touch
  the button as they pass under. `.rooms`'s top margin shrinks to match, so
  the resting layout looks as it does now.
- The `z-index` values matter: `.avatar` is `position: relative` and comes
  later in the document, so without them the discs would paint over the bar
  and the button.
- The bar's background is 600 px wide (its `max-width`), the same as the
  content, so nothing shows beside it.

### Testing

- `test/quickmeet/routes_test.lg`: the manifest's status, content type and
  that it parses as JSON with `display` `standalone`; each PNG's status,
  `image/png` type and PNG signature; `/favicon.ico`'s status and
  `image/x-icon` type; every page links the manifest.
- `e2e/tests/app.spec.js` (new): the manifest link resolves and its icons
  load; Back from the lobby, History and Settings lands on `/`; Back is not
  visible in a call; on a phone viewport with 25 rooms, after scrolling to
  the bottom, the nav and "New call" are still in the viewport and the bar's
  top is 0.
- On a device after deploy (manual, for the user, not part of execution):
  install on an iPhone and on Android, check the icon, that the camera works
  in the installed app, and Back. In Chrome, install from the browser's menu
  ("Install app" / "Add to Home screen"); Chrome's own install prompt has
  further criteria and may not appear. On the iPhone, check upright and
  sideways that the Back button in the lobby and the controls in a call
  clear the notch and the home indicator. Known behaviour to expect: an installed app
  on iOS has its own cookies (sign in again), and links tapped in other apps
  open Safari, not the installed app.
